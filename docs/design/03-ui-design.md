# 03 - UI/UX 设计文档

> 项目:多集群 Kubernetes 管理 Dashboard(内部代号 kubeUI)
> 技术栈:Vue 3 + TypeScript(前端)/ Go(后端)
> 目标设备:桌面浏览器为主,最小支持宽度 1280px,推荐 1440px / 1920px
> 主题:亮色 / 暗色双主题,暗色为运维用户默认推荐主题

---

## 1. 设计原则

针对 K8s 运维场景(长时间注视、高频切换、大量结构化数据、高危操作),确立以下 5 条原则:

1. **信息密度优先(Density First)**
   运维用户是专家而非新手,拒绝大留白营销式设计。表格默认紧凑模式,一行展示尽可能多的关键状态(副本数、Ready、重启次数、年龄),减少滚动与翻页。行高、字号以 12-14px 为主,牺牲少量美观换取单屏信息量。

2. **状态即语言(Status as Language)**
   集群健康、Pod 运行态、事件级别全部通过统一的语义色 + 徽章 + 图标三重编码表达,任何页面 1 秒内可扫读出异常项。颜色不是装饰,是数据:Running=绿、Pending=黄、Failed/CrashLoop=红、Terminating=灰、Succeeded=蓝。

3. **危险操作强确认(Danger Guard)**
   删除 Deployment/Node/集群、修改资源 YAML 等不可逆或影响面大的操作,一律使用**输入资源名称确认**的 Dialog,并明示影响范围(如"将删除 3 个副本及关联 Service")。平台级操作(删除集群注册、修改用户角色)要求二次输入确认。

4. **上下文不丢失(Context Persistence)**
   集群 / 命名空间 / 主题 / 表格筛选条件全部持久化(localStorage + URL query)。从列表跳详情再返回,筛选与滚动位置保留。日志与终端以抽屉形式覆盖在当前页面之上,不脱离资源上下文。

5. **暗色一等公民(Dark First Class)**
   暗色不是亮色的简单反色。所有色板、图表配色、代码高亮、徽章色均独立针对暗色调校;默认跟随系统,但顶栏一键切换并记住选择。

## 2. 视觉规范

### 2.1 色彩系统

#### 品牌主色

采用 Kubernetes 官方蓝作为品牌主色,与领域强关联、辨识度高:

| Token | 亮色模式 | 暗色模式 | 用途 |
|---|---|---|---|
| `--brand-primary` | `#326CE5` | `#5B8DEF` | 主按钮、链接、选中态、品牌元素 |
| `--brand-primary-hover` | `#2A5EC7` | `#7AA5F5` | hover |
| `--brand-primary-active` | `#2450AA` | `#326CE5` | active / 按下 |
| `--brand-primary-bg` | `#EAF0FC` | `#1B2A4A` | 选中行背景、Tag 底色 |

#### 语义色

| 语义 | 含义(K8s 映射) | 亮色(主色/底色) | 暗色(主色/底色) |
|---|---|---|---|
| 成功 Success | Running / Ready / Succeeded | `#16A34A` / `#E8F7EE` | `#4ADE80` / `#12291B` |

| 信息 Info | 中性事件 / 提示 | `#0E7490` / `#E6F6FA` | `#38BDF8` / `#0E2A36` |
| 中性 Neutral | Terminating / 未知 / 禁用 | `#6B7280` / `#F3F4F6` | `#9CA3AF` / `#2A2E35` |

`#326CE5`(品牌蓝)、`#8B5CF6`(紫)、`#06B6D4`(青)、`#F59E0B`(橙)、`#EC4899`(粉)、`#10B981`(绿)。暗色下全部提亮一档,详见 2.4。

### 2.2 字体与字号体系

| 用途 | 字体栈 |
|---|---|
| UI 正文 | `"Inter", "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", system-ui, sans-serif` |
| 代码 / YAML / 日志 / 终端 | `"JetBrains Mono", "Cascadia Code", "SFMono-Regular", Consolas, monospace` |
| 数字(K8s 资源量、指标) | 同 UI 正文,但开启 `font-variant-numeric: tabular-nums` 保证表格数字对齐 |

字号体系(基准 14px,密集表格场景可降档):

| Token | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `h1` | 20px / 28px | 600 | 页面标题 |
| `h2` | 16px / 24px | 600 | 卡片标题、Dialog 标题、区块标题 |
| `h3` | 14px / 22px | 600 | 小标题、Tab、表单 Label |
| `body` | 14px / 22px | 400 | 正文、表格常规单元格 |
| `body-sm` | 13px / 20px | 400 | 辅助描述、下拉选项 |
| `caption` | 12px / 18px | 400 | 徽章、时间戳、表头(紧凑表格) |
| `code` | 12.5px / 20px | 400 | YAML、日志、终端(等宽字体) |
| `code-lg` | 14px / 22px | 400 | Web 终端(全屏下可调 12-16px) |

规则:
- 同一表格内不允许出现两种正文字号;数字列一律 `tabular-nums` + 右对齐。
- YAML / 日志区必须等宽字体,禁止在等宽区使用比例字体。
- 中英混排行高统一 22px,避免中文换行跳动。

### 2.3 间距、圆角、阴影

**间距:基于 4px 网格**,可用值 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 48`。

| 场景 | 值 |
|---|---|
| 组件内(按钮内边距、单元格内边距) | 8-12px |
| 卡片内边距 | 16px(紧凑模式 12px) |
| 区块之间 | 24px |
| 页面容器左右内边距 | 24px |
| 表格行高 | 紧凑 36px / 标准 44px,列表页默认紧凑 |

**圆角:**

| 元素 | 圆角 |
|---|---|
| 按钮、输入框、下拉、徽章 | 4px |
| 卡片、面板、抽屉 | 8px |
| Dialog | 8px |
| 头像、状态圆点 | 圆形 |

**阴影(仅亮色模式显著,暗色降为边框+明度差):**

| 层级 | 亮色 | 暗色 |
|---|---|---|
| 卡片 | `0 1px 2px rgba(15,23,42,.06)` | 无阴影,`1px solid var(--border-1)` |
| 下拉/Popover | `0 4px 16px rgba(15,23,42,.12)` | 无阴影,`1px solid var(--border-2)` + 提亮 |
| Dialog / 抽屉 | `0 8px 32px rgba(15,23,42,.16)` | 无阴影,`1px solid var(--border-2)` |

### 2.4 图标规范

**选型结论:unplugin-icons + Iconify 的 Tabler Icons 集合**(`@iconify-json/tabler`),构建期按需内联为 SVG 组件,无运行时开销,TypeScript 类型完备。

- 线性风格(2px stroke),与 K8s 生态工具(Lens、Headlamp)的界面气质一致,密度高的界面上比面性图标更干净。
- 尺寸:导航 18px、按钮/表格操作 16px、徽章内 12px,统一 `stroke-width: 2`。
- K8s 资源类型图标(Deployment、StatefulSet、DaemonSet、Pod、Service、Ingress、Node 等)自绘一套 16×16 单色 SVG,与 Tabler 风格对齐,存于 `src/assets/icons/resources/`,通过自定义 `ResourceIcon` 组件按 kind 映射。
- 状态图标优先用语义色圆点(dot)而非图标,减少视觉噪音。

## 3. 组件库选型

**结论:Naive UI**(搭配 `naive-ui` 的 `NConfigProvider` 做全局主题 Token 注入)。

理由(对照本项目的三个硬指标):

1. **暗色主题质量**:Naive UI 原生内置完整暗色主题(`darkTheme`),所有组件(含 Select、DatePicker、Modal、Message)在暗色下经过成体系调校,无需逐组件覆盖;且支持 `themeOverrides` 深度定制 Token,可直接把本文 2.1 的色板映射进去。Element Plus 的暗色依赖 CSS var 手工补齐,Dialog/Select 等组件暗色细节一致性明显偏弱;Ant Design Vue 暗色可用但 Token 体系对 Vue 3 的适配滞后于 React 版。
2. **Tree / Table 大数据量**:K8s 资源树动辄数百节点、事件列表上万条。Naive UI 的 `n-data-table` 与 `n-tree` 原生支持虚拟滚动(virtual-scroll),这是 Element Plus(表格虚拟滚动需付费 Plus 版思路或自研)不具备的硬能力。
3. **可定制性**:Naive UI 全组件无内置强样式,主题 Token 化程度最高,便于实现双主题与后续品牌换肤;CSS-in-JS 方式天然支持运行时切换主题,切换零闪烁。
4. 辅助考量:纯 TypeScript 编写、按需 tree-shaking 体积友好、无对 CSS 预处理器的依赖。

补充选型:

| 领域 | 选择 | 说明 |
|---|---|---|
| 图表 | Apache ECharts(vue-echarts) | 监控时序图事实标准,暗色主题有官方配套 |
| 代码/YAML 编辑器 | CodeMirror 6(@codemirror/lang-yaml) | 轻量、启动快,YAML lint + 折行 + 搜索齐全 |
| 日志/终端渲染 | xterm.js(终端)/ 自研虚拟滚动日志视图 | xterm.js 是 Web 终端事实标准 |
| 状态管理 | Pinia | 官方推荐,负责集群/命名空间全局上下文 |
| 图标 | unplugin-icons + Tabler(见 2.4) | — |

### 4.3 左侧导航规范

- 平台级(始终可见):集群列表、用户与权限、审计日志。
- 集群级(选中集群后出现,顶部显示集群名 + 状态点 + 版本):按 K8s 资源域分组 —— 资源树(工作负载 / 配置 / 网络 / 存储)、诊断(事件 / 节点 / 监控)。
- 当前路由对应项高亮(`--brand-primary-bg` 底 + 左侧 2px 主色指示条);分组可折叠,折叠状态持久化。
- 宽度 232px,可折叠为 64px 图标态(仅平台级图标),折叠状态持久化。
- 底部固定"+ 注册集群"按钮,任何页面可一键发起注册向导。

### 4.5 终端 / 日志:抽屉还是独立页

**结论:右侧全高抽屉(Drawer),宽度 72%(最小 960px),顶部提供"全屏"按钮进入沉浸模式;不做独立页面。**

理由:
1. 用户从 Pod 详情点开日志/终端,典型动作是"看日志 → 回表格换一个 Pod → 再看",抽屉保留列表上下文,往返成本最低;独立页会打断筛选状态与浏览位置。
2. 日志流与终端常需要"边看日志边改 YAML / 查事件"的分屏操作,抽屉天然形成左侧列表 + 右侧面板的工作台布局。
3. 长时间专注排障场景(全屏看日志、终端敲命令)由"全屏"模式补足,地址栏同步 `?panel=logs&pod=xxx`,可直链分享、刷新不丢失。

### 5.2 集群总览仪表盘

## 6. 状态与反馈设计

### 6.1 空状态(Empty)

| 场景 | 视觉 | 行动 |
|---|---|---|
| 无集群 | 插画 + "注册你的第一个集群" | 主按钮 [注册集群] |
| 列表无数据(无筛选) | 简单图标 + "暂无 Deployment" | 主按钮 [创建资源] |
| 筛选无结果 | 搜索图标 + "没有匹配结果" | [清除筛选] |
| 无权限 | 锁图标 + "你没有该命名空间的访问权限,请联系管理员" | 无按钮,显示所需权限说明 |
| 集群失联 | 断线图标 + 上次同步时间 | [重试连接] [查看诊断] |

### 6.2 加载

- 首屏:页面骨架屏(标题条 + 卡片块 + 表格 8 行骨架),骨架块圆角 4px、呼吸动画 1.2s;**禁止**整页 spinner 遮罩。
- 表格刷新(已有数据):不显示骨架,表头右侧小 spinner + 数据静默替换,避免闪烁。
- 按钮 loading:提交类按钮点击后内联 spinner 并禁用;超过 300ms 才显示,避免快速操作闪烁。
- 长任务(生成下载链接、导出日志):按钮内进度或右下角 Toast 通知"完成后提醒"。

### 6.3 错误

- 请求失败:表格区顶部内联 Alert(危险色),含"重试";若用户正在编辑 YAML 保存失败,错误 Alert 内嵌于编辑器上方并保留用户输入(绝不清空)。
- WebSocket 断开(日志/终端):视图内顶部警示条"连接已断开 [重连]",重连成功自动清除。
- 401:全页跳登录;403:页面内错误态(见 6.1);409 冲突:按 5.4 YAML 冲突流程。
- 全局兜底:路由级 ErrorBoundary 页,展示错误 ID(便于关联后端日志)+ [返回首页] [刷新]。

### 6.4 危险操作确认模式

三级确认强度,按影响面选用:

| 级别 | 模式 | 适用 |
|---|---|---|
| L1 | 普通 Confirm(危险色主按钮) | 删除单个 Pod、重启工作负载 |
| L2 | **输入名称确认**:Dialog 中要求输入资源全名(如 `pay-svc`)才激活删除按钮;正文明示影响清单 | 删除 Deployment / Service / PVC(有数据!) |
| L3 | 输入名称确认 + 勾选"我已知晓影响" + 展示关联影响列表 | 删除集群注册、删除用户、级联删除 |

删除 Deployment 的 L2 Dialog 设计:

```
┌───────────────────────────────────────────────┐
│ ⚠ 删除 Deployment                        [✕] │
├───────────────────────────────────────────────┤
│ 即将永久删除:                                 │
│   Deployment  pay-svc  (namespace: pay)       │
│                                               │
│ 关联影响:                                     │
│  · 3 个 Pod 将被终止(pay-svc-7f9c-*)          │
│  · 2 个 ReplicaSet 历史将被清除                │
│  · Service "pay-svc" 不受影响,将指向空后端    │
│                                               │
│ 请输入资源名称以确认: [________________]      │
│ (输入 pay-svc 以启用删除)                     │
│                                               │
│                          [取消]  [删除](禁用→危险红)│
└───────────────────────────────────────────────┘
```

规则:
- 危险按钮确认后立即进入 loading,成功后 Toast"已删除 pay-svc",Toast 内提供 [撤销]?——**不提供**。K8s 删除不可靠撤销,仅对 Pod/Job 提供确认前"同步删除选项(grace period / --force)"勾选。
- 批量删除:Dialog 内列出全部待删资源(可再逐项取消勾选),名称确认输入要求输入 `删除 3 个 Deployment` 中的数字(如 `3`)或其中最关键资源名,取实现简单且可靠的"输入数量"方案。
- 所有危险操作前后均写入审计日志。

## 7. 信息密度与表格规范

### 7.1 通用列结构

`[选择框 32px] [状态 24px] [名称主列(弹性)] [辅助列×N(固定宽)] [时间列 90px] [操作 48px]`

- 名称列:主名称 `--text-1` 14px + 第二行 `--text-3` 12px 副信息(可选,如 Pod 所属节点);超长省略 + tooltip 全文 + [复制] 按钮。
- 操作列:固定右缘(fixed right),默认只显示 `⋯`,悬停行时显示 2 个最高频操作(如日志/终端)+ `⋯`。
- 表头:13px `--text-2`,600 字重,可排序列带箭头;列宽支持拖拽调整并持久化到 localStorage。
- 空单元格显示 `—`,不显示空白。

### 7.2 常用列表列定义

| 列表 | 列 |
|---|---|
| Pod | 状态点+名称 / Namespace / Ready(容器数) / 重启次数(>0 显黄、>5 显红) / 节点 / IP / AGE / 操作 |
| Deployment | 状态点+名称 / NS / Ready / Available / Up-to-date / AGE / 镜像 / 操作 |
| Node | 状态点+名称 / 角色 / 版本 / CPU(使用率条) / 内存(使用率条) / Pod 数 / 内部IP / AGE |
| Event | 级别徽章 / 最近时间 / 类型 / 原因 / 对象(kind/name,可点击) / 消息 / 次数 |
| 节点资源水位条:横条内填充语义色(≤60% 绿 / 60-90% 黄 / >90% 红)+ 右侧百分比数字 |

### 7.3 状态徽章规范

统一结构:`● 圆点(语义色)+ 文案`;文案优先用 K8s 原生术语,不翻译造词。

| 状态 | 色 | 文案示例 |
|---|---|---|
| Running / Ready / Connected / Bound | 成功绿 | `● Running` |
| Pending / ContainerCreating / 资源水位 60-90% | 警告黄 | `● Pending` |
| Failed / CrashLoopBackOff / ImagePullBackOff / NotReady / 失联 | 危险红 | `● CrashLoopBackOff` |
| Succeeded / Completed | 信息蓝 | `● Completed` |
| Terminating / Unknown / 禁用 | 中性灰 | `● Terminating` |
| 进行中任务(滚动更新中) | 品牌蓝 + 旋转图标 | `↻ Rolling Update` |

### 7.4 时间显示规则

- 列表/卡片:K8s 惯例**相对时间**(`5s / 3m / 2h / 12d`),等宽数字,列头为 `AGE`。
- 悬停任意相对时间 → tooltip 显示绝对时间 `2026-09-11 10:21:03 (UTC+8)`,并附 [复制]。
- 事件、审计日志等需要精确排序的列表:同时显示两列或显示绝对时间,相对时间仅用于概览。
- 所有绝对时间统一 `YYYY-MM-DD HH:mm:ss`,时区跟随浏览器,用户设置中可固定为 UTC(运维跨时区场景常见,UTC 切换是硬需求)。

## 8. 国际化与可访问性

### 8.1 国际化

- 框架:vue-i18n,locale 持久化到用户配置,跟随浏览器为初始值;中英文全量覆盖,zh-CN 为默认。
- 范围:导航、表头、按钮、Toast、错误文案全量翻译;**K8s 领域名词不翻译**(Running、Pending、CrashLoopBackOff、Ready、YAML),包括文档化说明中也保留英文,避免运维沟通歧义。
- 切换语言即时生效,无需刷新;`html lang` 同步更新。
- 文案规范:中文全角标点、英文与中文之间加空格("删除 3 个 Pod");i18n key 按 `<页面>.<区块>.<语义>` 命名(如 `deploy.list.col.ready`)。
- 预留文本膨胀空间:英文比中文长 30-60%,按钮/标签不写死宽度,容器可伸缩。

### 8.2 可访问性(面向专业用户的效率型 a11y)

- **键盘导航**:全局 `⌘K` 搜索、`g c` 类跳转可不做,但必须支持:`Tab` 顺序符合视觉流;表格行可聚焦,`Enter` 进入详情、`空格` 勾选、`L` 打开日志、`T` 打开终端(列表页快捷键,页脚提示条可关闭);`Esc` 关闭 Dialog/抽屉/全屏模式;Dialog 内焦点圈闭(focus trap),关闭后焦点归还触发元素。
- **焦点管理**:路由切换后焦点移至页面 `h1`;抽屉打开聚焦抽屉内第一个交互元素;所有可交互元素有可见焦点环(2px `--brand-primary` outline,offset 2px),暗色下同样清晰。
- 对比度:正文 `--text-1` 对 `--bg-surface` 对比度亮色 14:1 / 暗色 12:1;语义色文字在对应底色上 ≥4.5:1(黄、青在亮色底上使用深色变体保证)。
- 语义化:状态用文字徽章而非仅色点(色盲友好,色点始终伴随文字/数值);表格使用原生 `table` 语义,表头 `th scope`;图标按钮一律 `aria-label`。
- 动效:遵循 `prefers-reduced-motion`,关闭骨架呼吸、抽屉滑入动画。

## 附:设计决策速查
