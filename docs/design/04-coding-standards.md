### 1.2 放置规则

| 规则 | 说明 |
|---|---|
| 后端业务代码 **必须** 放 `backend/internal/` | `backend/pkg/` 只放确定对外通用的工具;顶层禁止散落 .go 文件 |
| handler **必须** 按资源一文件组织 | `handler/pod.go`,不按 HTTP 方法拆 |
| 新增前端接口 **必须** 先加类型再加函数 | `frontend/src/api/types.ts` 与 `backend/internal/model/` 保持同名同义 |
| 文档与代码放同一个 PR | 改接口必须同步改 `docs/api/` 与双端类型 |
| AI 代理 **禁止** 在仓库根目录创建临时脚本/笔记 | 临时产物放 `/tmp`,正式脚本放 `scripts/` 并评审 |
| 生成代码放 `*_gen.go` / `*.gen.ts` | 文件头标注 `// Code generated by ... DO NOT EDIT.`,生成代码不参与 lint 评审 |

## 2. Go 规范

基础版本:Go 1.23+。格式化以 `gofumpt` 为准,一切以 linter 结果为最终裁决。

### 2.1 包组织与命名

```go
// 包名:全小写、单个单词、不用复数、不用下划线
package cluster       // ✅
package k8sutils      // ⚠️ 避免,宁可叫 kube / kubeutil
package clusterService // ❌ 禁止大写
```

- 目录名 = 包名(例外:`cmd/server`)。
- 文件名全小写 + 下划线:`cluster_manager.go`、`handler_pod_test.go`。

**接口命名**:单方法接口用「动词-er」,多方法接口用名词;接口定义在**消费方**包,不在实现方。

```go
// ✅ 单方法
type Lister interface {
    List(ctx context.Context, ns string) ([]Pod, error)
}
// ✅ 多方法,名词
type ClusterRegistry interface {
    Get(ctx context.Context, name string) (*Cluster, error)
    Register(c *Cluster) error
    Unregister(name string) error
}
// ❌ 禁止 ICluster、ClusterInterface 这类匈牙利命名
```

**error 变量**:哨兵错误用 `Err` 前缀,集中在每个包的 `errors.go`:

```go
// internal/service/errors.go
var (
    ErrClusterNotFound   = errors.New("cluster not found")
    ErrClusterConnecting = errors.New("cluster is connecting")
)
// ❌ 禁止 var ClusterNotFound = ... (无 Err 前缀)
```

**JSON tag 规则**:

- 一律 `lowerCamelCase`,每个导出结构体字段 **必须** 显式写 tag,禁止依赖默认名。
- 时间字段统一 `time.Time` + tag `time.RFC3339` 序列化。
- 需要忽略的字段显式 `json:"-"`。

```go
type PodSummary struct {
    Name              string            `json:"name"`
    Namespace         string            `json:"namespace"`
    Status            string            `json:"status"`
    RestartCount      int32             `json:"restartCount"`
    CreatedAt         time.Time         `json:"createdAt"`
    Labels            map[string]string `json:"labels,omitempty"`
    InternalRuntimeID string            `json:"-"` // 不对外暴露
}
```

### 2.2 错误处理

**(1) 包装规则**:凡是被上层消费的错误 **必须** 用 `%w` 包装并带上下文动词,底层细节不允许丢:

```go
if err := r.client.Get(ctx, key, pod); err != nil {
    return fmt.Errorf("get pod %s/%s: %w", ns, name, err)
}
// ❌ return err  直接透传丢失上下文(调用链最底层一跳除外)
// ❌ fmt.Errorf("get pod: %v", err)  用 %v 切断错误链
```

**(2) 自定义错误类型**:带业务语义的错误统一实现 `*errcode.Error`:

```go
// internal/pkg/errcode/errcode.go
package errcode

type Error struct {
    Code    int    // 业务错误码,见错误码表
    Message string // 面向用户的稳定文案(可国际化)
    Cause   error  // 内部原因,不出现在 HTTP 响应中
}

func (e *Error) Error() string { return e.Message }
func (e *Error) Unwrap() error { return e.Cause }

func New(code int, message string) *Error { return &Error{Code: code, Message: message} }
func (e *Error) Wrap(err error) *Error { e2 := *e; e2.Cause = err; return &e2 }
```

错误码集中定义在 `internal/pkg/errcode/codes.go`,分段分配,**禁止**散落各文件随口编数字:

```go
// 段位约定:2xxxx 成功类无需定义;4xxxx 客户端错误;5xxxx 服务端错误
const (
    ClusterNotFound       = 40401 // cluster not found
    ClusterKubeconfigBad  = 40402 // invalid kubeconfig
    PodNotFound           = 40410
    ParamInvalid          = 40001
    InternalError         = 50000
    UpstreamK8sError      = 50100 // 访问用户集群失败
)
```

**(3) HTTP 错误响应映射**:handler 层统一出口,service 层 **禁止** 直接写 http.Status*:

```go
// internal/api/response/response.go
package response

func OK(c *gin.Context, data any) {
    c.JSON(http.StatusOK, gin.H{"code": 0, "message": "ok", "data": data})
}

func Fail(c *gin.Context, err error) {
    var ec *errcode.Error
    if errors.As(err, &ec) {
        c.JSON(httpStatusOf(ec.Code), gin.H{"code": ec.Code, "message": ec.Message, "data": nil})
        return
    }
    // 未知错误:对外一律 50000,内部原因只进日志
    log.Error(c.Request.Context(), "unhandled error", "err", err)
    c.JSON(http.StatusInternalServerError, gin.H{"code": 50000, "message": "internal error", "data": nil})
}

func httpStatusOf(code int) int {
    switch {
    case code >= 40000 && code < 40500:
        return http.StatusBadRequest
    case code >= 40400 && code < 40500:
        return http.StatusNotFound
    case code >= 50000:
        return http.StatusInternalServerError
    }
    return http.StatusInternalServerError
}
```

判定业务错误一律 `errors.Is` / `errors.As`,**禁止** 字符串匹配 `err.Error()`。

### 2.3 context 传递与超时

- `context.Context` **必须** 是每个函数第一个参数,命名固定 `ctx`。
- **禁止** 把 ctx 存进 struct 字段;**禁止** `context.Background()` 出现在请求链路中(main、server 启动、后台任务入口除外)。
- 每个出站调用(K8s API、子查询)**必须** 有超时:

```go
// K8s 读操作
ctx, cancel := context.WithTimeout(ctx, 10*time.Second)
defer cancel()
podList, err := r.client.CoreV1().Pods(ns).List(ctx, opts)
```

- `defer cancel()` **必须** 与 `WithTimeout`/`WithCancel` 成对出现(lint 强制)。
- HTTP handler 的整体超时由 `http.Server{ReadTimeout, WriteTimeout}` + 中间件 `context.WithTimeout(r.Context(), 30*time.Second)` 双保险。
- 多集群聚合查询允许 `context.WithoutCancel` 保留 trace/requestid,但 **必须** 显式重新设置超时。

### 2.4 并发规范

**默认禁裸 `go`,必须满足以下条件之一才允许:**

1. 使用 `errgroup`(有错误收集、panic 转发、ctx 派生);
2. 有生命周期管理的 worker(收到 ctx.Done 或 close 信号退出);
3. main / server 关闭路径中的受控启动。

```go
// ✅ 并发查多个集群:errgroup + 本地变量捕获
g, gctx := errgroup.WithContext(ctx)
g.SetLimit(8) // 有界并发,禁止无界
results := make([]ClusterStatus, len(clusters))
for i, c := range clusters {
    i, c := i, c // Go <1.22 才需要;1.22+ 可省,但省略前确认 go.mod 版本
    g.Go(func() error {
        st, err := probeCluster(gctx, c)
        if err != nil {
            return fmt.Errorf("probe cluster %s: %w", c.Name, err)
        }
        results[i] = *st
        return nil
    })
}
if err := g.Wait(); err != nil {
    return fmt.Errorf("probe clusters: %w", err)
}
```

**goroutine 泄漏防护四条铁律:**

1. 每个 goroutine **必须** 有明确退出条件(ctx / channel close / WaitGroup);
2. 启动 goroutine 的函数 **必须** 说明"谁负责停止它"(写在 godoc 里);
3. channel 方向:发送方 close,接收方 **禁止** close;
4. 带缓冲 channel + select + ctx.Done 组合,防止发送阻塞。

```go
// ✅ 长驻 worker:ctx 驱动退出
func (w *Watcher) Run(ctx context.Context) error {
    for {
        select {
        case <-ctx.Done():
            return ctx.Err()
        case ev := <-w.events:
            if err := w.handle(ctx, ev); err != nil {
                log.Warn(ctx, "handle event failed", "err", err)
            }
        }
    }
}
```

共享状态:优先 channel;确需 mutex 时用 `sync.Mutex`(不导出),`go test -race` **必须** 通过。

### 2.5 日志规范

**选型:标准库 `log/slog`**(单二进制 + 新项目,无需 zap 的性能极限;JSON handler 输出)。封装在 `internal/pkg/logx`,全局只通过封装调用, **禁止** 直接 `fmt.Println` / `log.Print` / `log.Fatal`(main 除外)。

```go
// internal/pkg/logx/logx.go
package logx

var L *slog.Logger

func Init(level, format string) { /* slog.NewJSONHandler 或 TextHandler */ }
func Debug(ctx context.Context, msg string, args ...any) { L.DebugContext(ctx, msg, args...) }
func Info(ctx context.Context, msg string, args ...any)  { L.InfoContext(ctx, msg, args...) }
func Warn(ctx context.Context, msg string, args ...any)  { L.WarnContext(ctx, msg, args...) }
func Error(ctx context.Context, msg string, args ...any) { L.ErrorContext(ctx, msg, args...) }
```

**必须携带的结构化字段**(由 requestid 中间件注入 request_id;业务代码负责其余):

| 字段 | 类型 | 何时必须 |
|---|---|---|
| `cluster` | string | 涉及某个集群的所有日志 |
| `namespace` | string | 涉及命名空间资源的日志 |
| `resource` / `resource_type` | string | 涉及具体资源(pod/deployment...)的日志 |
| `request_id` | string | 所有请求链路日志(中间件统一注入) |
| `err` | error | 所有 error/warn 日志 |
| `duration_ms` | int | 出站调用、耗时操作 |

```go
logx.Error(ctx, "list pods failed",
    "cluster", clusterName,
    "namespace", ns,
    "resource_type", "pod",
    "err", err,
)
// ❌ logx.Error(ctx, fmt.Sprintf("list pods in %s failed: %v", ns, err))  禁止拼字符串日志
```

消息是小写短句、常量风格;键是 `lowerCamel` 固定字符串;日志级别:Debug=开发细节,Info=状态迁移/启动事件,Warn=可自动恢复异常,Error=需要人介入。**禁止** 在日志里输出 kubeconfig、token、secret 内容。

### 2.6 注释与 godoc

- 所有导出的类型、函数、常量 **必须** 有 godoc 注释,以标识符名开头、完整句子:
  `// ListPods returns pod summaries of the given cluster and namespace.`
- 私有函数仅在与直觉不符时注释;**不写**复述代码的注释(`// increase i by 1`)。
- 三种场景 **必须** 写注释:
  1. 并发/生命周期:谁起 goroutine、谁负责停、线程安全与否;
  2. 与 K8s API 行为相关的 workaround(注明 k8s issue 链接);
  3. 错误码、协议常量的含义。
- `TODO` / `FIXME` 必须带负责人与 issue:`// TODO(zhangsan #123): ...`,CI grep 无主 TODO 即失败。
- 每个非 trivial 包可有一个 `doc.go` 放包级说明。

### 2.7 测试规范

- **表驱动测试** 为默认写法,测试函数名 `Test<被测函数>` + 子测试 `t.Run`:

```go
func TestParsePagination(t *testing.T) {
    tests := []struct {
        name    string
        page    string
        size    string
        want    Pagination
        wantErr bool
    }{
        {name: "defaults on empty", page: "", size: "", want: Pagination{Page: 1, Size: 20}},
        {name: "negative page", page: "-1", size: "10", wantErr: true},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := ParsePagination(tt.page, tt.size)
            if (err != nil) != tt.wantErr {
                t.Fatalf("err = %v, wantErr %v", err, tt.wantErr)
            }
            if got != tt.want {
                t.Fatalf("got %+v, want %+v", got, tt.want)
            }
        })
    }
}
```

- 断言用标准库 `t.Errorf/Fatalf` 或 `stretchr/testify`(assert/require,同一文件内不混用)。
- **覆盖率**:`make test` 要求 `internal/` 总行覆盖率 ≥ 60%,`service/`、`pkg/` ≥ 75%(go.testcoverage 汇总打印,CI 卡阈值)。
- **client-go fake client 用法**:所有不真正连集群的 K8s 逻辑 **必须** 用 fake client,禁止为了单测连真实集群:

```go
import (
    k8stesting "k8s.io/client-go/kubernetes/fake"
    k8stestingcore "k8s.io/client-go/kubernetes/typed/core/v1/fake"
    testing "k8s.io/client-go/testing"
)

func TestPodLister(t *testing.T) {
    client := k8stesting.NewSimpleClientset(
        &corev1.Pod{ObjectMeta: metav1.ObjectMeta{Name: "web", Namespace: "default"}},
    )
    // 需要 PrependReactor 模拟错误:
    // client.Fake.PrependReactor("list", "pods",
    //     func(action testing.Action) (bool, runtime.Object, error) {
    //         return true, nil, errors.New("etcd timeout")
    //     })
    got, err := NewPodLister(client).List(context.Background(), "default")
    require.NoError(t, err)
    require.Len(t, got, 1)
}
```

- 动态 client / informer 场景用 `dynamic/fake` 与 `k8s.io/client-go/tools/cache` 的测试工具;测试文件一律 `*_test.go` 与被测代码同包,公共测试助手放 `internal/k8s/fake/`。
- 测试里 **禁止** `time.Sleep` 等待(用 `wait.PollUntilContextTimeout` 或 channel 同步);外部依赖(HTTP)用 `httptest`。

### 2.9 Go 明确禁止事项

1. **禁止** `panic` 用于业务错误(main/recovery 中间件、不可恢复的初始化错误除外)。
2. **禁止** `init()` 中做 IO、读配置、起 goroutine(仅允许纯内存常量初始化)。
3. **禁止** 全局可变单例承载业务状态(依赖通过构造函数注入)。
4. **禁止** `interface{}`/`any` 出现在对外 API 的请求/响应结构体中(响应 data 用 `any` 的统一封装除外)。
5. **禁止** 用 `%v` 包装错误;禁止字符串比较判断错误。
6. **禁止** 无界 goroutine、无退出条件的 for 循环 channel。
7. **禁止** 在 struct 中保存 `context.Context`。
8. **禁止** 提交 `vendor/`、`bin/`、测试产物。
9. **禁止** 直接 `fmt.Println` 调试输出入库。
10. **禁止** 在 `internal/api` 之外的层 import `net/http`(读取 HTTP 语义)或 gin。
11. **禁止** 硬编码 kubeconfig 路径、token、集群地址(必须走 config/env)。
12. **禁止** 忽略 errcheck 报错而不写豁免理由。

## 3. TypeScript / Vue 规范

基础版本:TypeScript 5.x(strict),Vue 3.4+,Vite 5+,Pinia 2+。

### 3.1 组合式 API

- **强制** `<script setup lang="ts">`, **禁止** Options API 与 `defineComponent` 的 options 写法(库级包装组件除外)。
- `<script setup>` 内代码顺序约定:`defineProps/defineEmits` → 依赖注入/store → 响应式状态 → computed → 生命周期 → 函数 → 逻辑返回。
- **禁止** `this`(不存在)、**禁止** `Vue.prototype` 挂载、**禁止** mixin(逻辑复用一律 composable)。

```vue
<script setup lang="ts">
import { computed, ref } from 'vue'
import type { PodSummary } from '@/api/types'

const props = defineProps<{ pod: PodSummary; selectable?: boolean }>()
const emit = defineEmits<{ select: [pod: PodSummary] }>()

const active = ref(false)
const displayStatus = computed(() => props.pod.status.toUpperCase())

function onSelect(): void {
  emit('select', props.pod)
}
</script>

<template>
  <!-- 模板中禁止复杂表达式,一律用 computed -->
  <tr :class="{ active }" @click="onSelect">
    <td>{{ props.pod.name }}</td>
    <td>{{ displayStatus }}</td>
  </tr>
</template>
```

- 模板表达式只允许一元/成员访问/单个函数调用;一切派生逻辑进 `computed` 或函数。

### 3.2 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 组件文件 | 大驼峰 `.vue`,多单词强制 | `PodTable.vue`、`BaseModal.vue`、`ClusterSelector.vue` |
| base 原子组件 | `Base` 前缀 | `BaseButton.vue` |
| 组件名(模板注册) | 与文件同名大驼峰,模板中使用 `<PodTable>` | — |
| composable 文件/函数 | `useXxx.ts` / `useXxx()` | `useClusterList.ts` → `useClusterList()` |
| 普通 ts 模块 | 小驼峰 | `formatBytes.ts` |
| 类型/接口 | 大驼峰,**禁止** `I` 前缀 | `ClusterInfo`(❌ `IClusterInfo`) |
| 类型别名 vs interface | 对象形状用 `interface`,联合/工具类型用 `type` | — |
| 常量 | `UPPER_SNAKE_CASE` | `const MAX_POLL_INTERVAL_MS = 30_000` |

| 路由 `name` | 大驼峰与组件对应 | `name: 'ClusterDetail'` |

### 3.3 Pinia 状态管理

**Store 划分规则:按后端资源域划分,一个资源域一个 store,禁止做"万能 store"。**

```text
stores/
├── clusterStore.ts    # 多集群注册信息、当前选中集群
├── workloadStore.ts   # Pod/Deployment/StatefulSet 等工作负载列表与筛选
├── eventStore.ts      # 事件流(WebSocket 推送)
├── authStore.ts       # 登录态、用户信息
└── uiStore.ts         # 全局 UI 状态(侧边栏、主题)
```

约束:

1. store 文件用 **setup store 写法**(`defineStore('cluster', () => {...})`),与组合式 API 统一;
2. id 与文件名一致(`useClusterStore` → id `cluster`);
3. store 内 **禁止** 直接 `fetch`,必须调用 `src/api/` 模块;
4. 服务器数据缓存、分页、轮询逻辑放 store;纯组件内部状态(输入框、modal 开关) **禁止** 进 store;
5. store 之间 **禁止** 循环依赖;跨 store 组合在 composable 中完成;
6. 需要 SSR 持久化的状态才用 plugin,当前项目不启用。

```ts
// src/stores/clusterStore.ts
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'
import { listClusters } from '@/api/cluster'
import type { ClusterInfo } from '@/api/types'

export const useClusterStore = defineStore('cluster', () => {
  const clusters = ref<ClusterInfo[]>([])
  const currentName = ref<string>('')
  const loading = ref(false)

  const current = computed(() => clusters.value.find((c) => c.name === currentName.value))

  async function fetchClusters(): Promise<void> {
    loading.value = true
    try {
      clusters.value = await listClusters()
      if (!current.value && clusters.value.length > 0) {
        currentName.value = clusters.value[0].name
      }
    } finally {
      loading.value = false
    }
  }

  return { clusters, currentName, loading, current, fetchClusters }
})
```

### 3.5 API 层封装

- 唯一网络出口是 `src/api/http.ts`;**禁止** 在组件/store/composable 内出现 `fetch`/`axios`/`XMLHttpRequest`(lint 规则强制)。

```ts
// src/api/http.ts
import { useAuthStore } from '@/stores/authStore'
import type { ApiResponse } from './types'

const BASE = '/api/v1'

export class ApiError extends Error {
  constructor(
    public readonly code: number,
    message: string,
    public readonly httpStatus: number,
  ) {
    super(message)
    this.name = 'ApiError'
  }
}

async function request<T>(path: string, init?: RequestInit): Promise<T> {
  const auth = useAuthStore()
  const resp = await fetch(`${BASE}${path}`, {
    ...init,
    headers: {
      'Content-Type': 'application/json',
      ...(auth.token ? { Authorization: `Bearer ${auth.token}` } : {}),
      ...init?.headers,
    },
  })
  if (resp.status === 401) {
    await auth.logout()
    throw new ApiError(40100, 'unauthorized', 401)
  }
  const body = (await resp.json()) as ApiResponse<T>
  if (body.code !== 0) {
    throw new ApiError(body.code, body.message, resp.status) // 与后端错误码(§4.2)对应
  }
  return body.data
}

export const http = {
  get: <T>(path: string) => request<T>(path),
  post: <T>(path: string, body: unknown) =>
    request<T>(path, { method: 'POST', body: JSON.stringify(body) }),
  delete: <T>(path: string) => request<T>(path, { method: 'DELETE' }),
}
```

- 每个资源一个模块,函数按「动词 + 资源」命名,必须显式标注返回类型:

```ts
// src/api/cluster.ts
import { http } from './http'
import type { ClusterInfo, PageResult, PodSummary } from './types'

export function listClusters(): Promise<ClusterInfo[]> {
  return http.get<ClusterInfo[]>('/clusters')
}

export function listPods(cluster: string, ns: string, query: PaginationQuery): Promise<PageResult<PodSummary>> {
  const qs = new URLSearchParams({
    cluster,
    namespace: ns,
    page: String(query.page),
    size: String(query.size),
  })
  return http.get<PageResult<PodSummary>>(`/pods?${qs}`)
}
```

- WebSocket 连接同样封装到 `src/api/ws.ts`(见 §4.5),组件只消费 `useResourceWatch` composable。

## 4. 接口契约规范

### 4.1 REST 路由命名

统一前缀 `/api/v1`。资源用复数小写连字符,层级不超过两级;非 CRUD 动作用资源下的 **动词子资源**:

```text
GET    /api/v1/clusters                          # 列出已注册集群
POST   /api/v1/clusters                          # 注册集群(kubeconfig)
DELETE /api/v1/clusters/{cluster}                # 注销集群
GET    /api/v1/clusters/{cluster}/status         # 集群连接状态(动作子资源)

GET    /api/v1/clusters/{cluster}/pods           # 列出 Pod(跨 namespace 用 ?namespace=)
GET    /api/v1/clusters/{cluster}/pods/{name}    # Pod 详情
GET    /api/v1/clusters/{cluster}/pods/{name}/logs   # 动作:取日志 ?container=&tailLines=
POST   /api/v1/clusters/{cluster}/pods/{name}/restart
DELETE /api/v1/clusters/{cluster}/namespaces/{namespace}/pods/{name}
```

规则:

1. 名称全小写,多词用连字符(`virtualmachines`、`kube-config` 不用驼峰);
2. **禁止** 动词出现在资源位(❌ `GET /api/v1/getPods`);
3. 跨集群资源一律显式带 `{cluster}` 路径段, **禁止** 靠 header 隐式选集群(可读性、可测试性);
4. 过滤/排序一律 query 参数:`?namespace=&labelSelector=&sortBy=createdAt&order=desc`;
5. WebSocket 端点:`/api/v1/watch`。

### 4.2 统一响应体(双端示例)

Go 结构体(`internal/api/response/response.go`):

```go
type Body struct {
    Code    int    `json:"code"`              // 0 成功;非 0 见 errcode/codes.go
    Message string `json:"message"`           // 稳定文案,code=0 时固定 "ok"
    Data    any    `json:"data"`              // 失败时为 null
}
```

成功:

```json
{ "code": 0, "message": "ok", "data": { "name": "prod-eu", "status": "ready" } }
```

失败:

```json
{ "code": 40401, "message": "cluster not found", "data": null }
```

TS 类型(`src/api/types.ts`):

```ts
export interface ApiResponse<T> {
  code: number
  message: string
  data: T
}
```

约定:**所有** JSON 接口(含 DELETE)都用该包裹;错误码语义与 HTTP status 一致(见 §2.2 分段)。前端业务判断只看 `code`,HTTP status 仅用于 401/5xx 全局拦截。

### 4.3 分页约定

请求参数(所有列表接口统一):

| 参数 | 默认 | 约束 |
|---|---|---|
| `page` | 1 | ≥ 1 |
| `size` | 20 | 1–200,超出取 200 |
| `sortBy` | 各接口默认值 | 白名单枚举,非法值返回 40001 |
| `order` | `desc` | `asc` / `desc` |

响应 data:

```json
{ "items": [], "total": 137, "page": 2, "size": 20 }
```

Go:`internal/pkg/pagination` 提供 `Parse(r)` 与 `Result(items, total, p)`;K8s 原生 list 无 total 时用 `continue` token 做游标分页,data 形如 `{"items": [...], "continueToken": "..."}`,此时 **省略** total 字段并在 `docs/api/` 标注"游标分页"。

### 4.4 API 版本策略

- 路径版本 `/api/v1`;**禁止** 在 header/query 中做版本协商。
- v1 内只做向后兼容变更:新增可选字段、新增端点;**禁止** 删除/改名字段、改字段类型、改错误码语义。
- 破坏性变更 → `/api/v2`,旧版本保留至少一个大版本周期,并在响应 header 加 `Deprecation: true` + `Sunset` 日期。
- 前端只依赖 `VITE_API_BASE`(默认 `/api/v1`), **禁止** 硬编码版本号到组件代码。

### 4.5 WebSocket 消息协议

单端点 `/api/v1/watch`,协议为 JSON 文本帧,`type` 判别联合。连接建立后客户端先发 subscribe;服务端按 `requestId` 回执。

**Go 端类型(`internal/pkg/wsx/protocol.go`):**

```go
package wsx

type Envelope struct {
    Type      string          `json:"type"`                // subscribe|unsubscribe|event|ping|pong
    RequestID string          `json:"requestId,omitempty"` // subscribe 回执关联
    Payload   json.RawMessage `json:"payload,omitempty"`
}

type SubscribePayload struct {
    Cluster   string `json:"cluster"`
    Namespace string `json:"namespace,omitempty"` // 空 = 全部
    Resource  string `json:"resource"`            // pods|deployments|events
}

type EventPayload struct {
    Resource  string    `json:"resource"`
    Cluster   string    `json:"cluster"`
    Namespace string    `json:"namespace"`
    Name      string    `json:"name"`
    Action    string    `json:"action"` // added|modified|deleted
    Object    any       `json:"object"` // 与 REST 返回的 DTO 相同结构
}
```

**TS 端类型(`src/api/ws.ts`):**

```ts
export type WsEnvelope =
  | { type: 'subscribe'; requestId: string; payload: WsSubscribe }
  | { type: 'unsubscribe'; requestId: string; payload: Pick<WsSubscribe, 'resource' | 'cluster'> }
  | { type: 'event'; payload: WsEvent }
  | { type: 'pong' }

export interface WsSubscribe {
  cluster: string
  namespace?: string
  resource: 'pods' | 'deployments' | 'events'
}

export interface WsEvent {
  resource: string
  cluster: string
  namespace: string
  name: string
  action: 'added' | 'modified' | 'deleted'
  object: PodSummary // 与 REST DTO 同类型,按 resource 收敛为联合
}
```

协议约束:

1. 心跳:客户端每 25s 发 `{"type":"ping"}`,服务端回 `pong`;30s 无任何帧服务端断开,前端自动重连(指数退避 1s→30s + 抖动);
2. 前端 **禁止** 自行拼 WS URL,统一走 `useResourceWatch` composable(管理订阅集合、重连、组件卸载时 unsubscribe);
3. 协议变更必须同时修改双端类型并更新 `docs/api/websocket.md`,同 PR 提交。

## 5. Git 工作流

### 5.1 分支模型

## 6. 质量门禁

### 6.1 Makefile

```makefile
# ---- backend ----
BACKEND_DIR := backend

.PHONY: lint lint-backend lint-frontend fmt test test-backend test-frontend build clean

lint: lint-backend lint-frontend

lint-backend:
	cd $(BACKEND_DIR) && gofumpt -l -w . && golangci-lint run

lint-frontend:
	cd frontend && pnpm eslint . --max-warnings 0 && pnpm prettier --check .

fmt:
	cd $(BACKEND_DIR) && gofumpt -w .
	cd frontend && pnpm prettier --write .

test: test-backend test-frontend

test-backend:
	cd $(BACKEND_DIR) && go test -race -covermode=atomic -coverprofile=cover.out ./... \
		&& go tool cover -func=cover.out | tail -1

test-frontend:
	cd frontend && pnpm typecheck && pnpm vitest run --coverage

build: build-backend build-frontend

build-backend:
	cd $(BACKEND_DIR) && CGO_ENABLED=0 go build -ldflags="-s -w -X main.version=$(shell git describe --tags --always)" -o ../bin/kubeui-server ./cmd/server

build-frontend:
	cd frontend && pnpm build

clean:
	rm -rf bin backend/cover.out
```

前端 `package.json` scripts 约定:`typecheck` = `vue-tsc --noEmit`;`lint` = `eslint . --max-warnings 0`;`test` = `vitest run --coverage`。

### 6.2 CI 流水线(`.github/workflows/ci.yml` 概要)

```yaml
name: ci
on:
  pull_request:
  push: { branches: [main] }

jobs:
  commitlint:
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - run: npx --yes commitlint --from origin/${{ github.base_ref }} --to HEAD

  backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version-file: backend/go.mod, cache-dependency-path: backend/go.sum }
      - run: gofumpt -l . && test -z "$(gofumpt -l .)"     # working dir: backend
        working-directory: backend
      - run: golangci-lint run
        working-directory: backend
      - run: go test -race -covermode=atomic -coverprofile=cover.out ./...
        working-directory: backend
      - run: go tool cover -func=cover.out                  # 阈值由脚本 grep 校验
        working-directory: backend

  frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: pnpm, cache-dependency-path: frontend/pnpm-lock.yaml }
      - run: pnpm install --frozen-lockfile
        working-directory: frontend
      - run: pnpm typecheck && pnpm lint && pnpm test
        working-directory: frontend

  build:
    needs: [backend, frontend]
    steps:
      - run: make build                                      # 产出单二进制镜像
      - uses: docker/build-push-action@v6                    # 仅 main/tag 分支推送镜像
```

阶段顺序:`commitlint → backend(lint+test) → frontend(typecheck+lint+test) → build`。任何阶段失败即门禁失败; **禁止** 在 CI 中 `continue-on-error` 或跳过步骤。

### 6.3 本地最低要求

开发者/AI 提交前 **必须** 在本地执行(或等价的 pre-push hook):

```bash
make lint && make test
```

## 7. 文档规范

### 7.1 什么必须写文档

| 事项 | 文档位置 | 时机 |
|---|---|---|
| 新增/修改 REST 或 WS 接口 | `docs/api/`(路径、参数、响应、错误码) | 同一 PR |
| 影响架构/技术选型的决策 | `docs/design/adr/NNNN-xxx.md` | 决策落地前 |
| 新增目录、改变分层依赖规则 | 更新本文档 §1 | 同一 PR |
| 错误码新增 | `errcode/codes.go` 注释 + `docs/api/errors.md` | 同一 PR |
| 部署方式、配置项变更 | `deploy/` 与 `README` 部署章节 | 同一 PR |
| 复杂算法/协议(如 WS 心跳重连) | 代码 godoc/JSDoc 为主,超过 20 行设计说明进 `docs/design/` | 同一 PR |

规则:**代码即文档的第一来源**,文档只写"代码看不出来的东西"(为什么这么做、约束、坑)。 **禁止** 维护会过期复述代码的文档。

### 7.2 ADR 模板(`docs/design/adr/NNNN-title.md`)

```markdown
# ADR-NNNN: <决策标题>

- 状态: proposed | accepted | superseded by ADR-MMMM
- 日期: YYYY-MM-DD
- 决策人: <姓名/角色>

## 背景与问题
<为什么现在需要做这个决策,现状与约束是什么>

## 备选方案
1. 方案 A — <一句话描述>
   - 优点 / 缺点
2. 方案 B — ...

## 决策
<选定方案,一句话可执行的结论>

## 影响
<带来的约束、需要 follow-up 的事项、对既有规范(如本文档)的修订>

## 后果回溯(可选,6 个月后补充)
<实际效果与预期的偏差>
```

编号四位递增不重用;状态 `superseded` 的 ADR 保留不删除。以下决策至少必须以 ADR 形式记录:K8s 访问方式(client-go vs 直连 API)、多集群凭证管理、WS 协议、错误码体系、前端状态划分。

### 7.3 文档写作约束

- 设计文档语言:中文,代码/标识符保留英文;代码示例 **必须** 可编译/可运行。
- 每篇文档头部写"适用范围"与"最后更新时间"。
- AI 生成文档 **必须** 标注来源与假设(`> 注:本节假设 ...`),评审人负责核实后去除标注。
